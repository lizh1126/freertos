# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Coding behavior

**Tradeoff:** These guidelines bias toward caution over speed. For trivial tasks, use judgment.

### Think before coding

- State your assumptions explicitly. If uncertain, ask.
- If multiple interpretations exist, present them — don't pick silently.
- If a simpler approach exists, say so. Push back when warranted.
- If something is unclear, stop. Name what's confusing. Ask.

### Simplicity first

- No features beyond what was asked.
- No abstractions for single-use code.
- No "flexibility" or "configurability" that wasn't requested.
- No error handling for impossible scenarios.
- If 200 lines could be 50, rewrite it.

### Surgical changes

- Don't "improve" adjacent code, comments, or formatting.
- Don't refactor things that aren't broken.
- Match existing style, even if you'd do it differently.
- If you notice unrelated dead code, mention it — don't delete it.
- Remove imports/variables/functions that YOUR changes made unused.
- Don't remove pre-existing dead code unless asked.

### Goal-driven execution

- Transform tasks into verifiable goals. State a brief plan for multi-step tasks.
- Strong success criteria let you work independently. Weak criteria ("make it work") require constant clarification.

## Project overview

STM32H743 FreeRTOS project generated by STM32CubeMX, built with **Keil MDK-ARM** (ARM Compiler 5/6, not GCC/Make). The `.ioc` file is the CubeMX project configuration — code regenerated from it will overwrite non-USER-code regions.

## Build

Open `MDK-ARM/stm32h743_freertos.uvprojx` in Keil uVision and build (F7). There is no CLI make/cmake build.


## BSP driver pattern

BSP drivers use an opaque struct pattern:
- Public header declares `typedef struct led_dev led_dev_t` and exposes `extern const led_dev_t bsp_led1`
- `.c` file defines the real struct (`led_hw_t` for hardware params, `led_dev` with name + hw pointer) as a static const instance
- API functions (`led_init`, `led_ctl`, `led_toggle`) take the opaque pointer and delegate to static `_impl` functions

New peripherals should follow the same pattern: opaque struct in header, hardware details as static const in the `.c` file.

## FreeRTOS

- CMSIS-RTOS v2 API (`cmsis_os2.h`) — use `osThreadNew`, `osDelay`, `osMutexNew`, etc., not native FreeRTOS APIs
- Task creation is wired in `Core/Src/freertos.c` inside `MX_FREERTOS_Init()` under the `RTOS_THREADS` USER CODE section
- Stack is in words: `128 * 4` = 512 bytes

## MCU specifics

- STM32H743XI (Cortex-M7, single core)
- Define: `STM32H743xx`, `USE_HAL_DRIVER`
- System clock: HSE → PLL (5/192/2) → 480 MHz SYSCLK, AHB @ 240 MHz, APB @ 120 MHz
- MPU configured with background region (full 4GB, privileged default)
- LED pin: PE3 (active high)
- Key pin: PE13
- Timebase: TIM1 (not SysTick — SysTick is reserved for FreeRTOS)
